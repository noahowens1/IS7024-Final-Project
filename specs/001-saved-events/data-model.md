# Data Model: Saved Events

## User

Represents an authenticated account managed by ASP.NET Core Identity.

| Field | Meaning | Rules |
|---|---|---|
| `Id` | Stable Identity user identifier | Generated by Identity; never accepted from a save/remove form as authority |
| `UserName` | Account sign-in name | Managed and validated by Identity |
| `Email` | Account contact/sign-in data | Managed and validated by Identity |

Relationships: one user may have many saved-event records. User identity for
feature operations comes from the authenticated server-side principal.

## Event

Represents an event available to the application, independent of which source
supplied it.

| Field | Meaning | Rules |
|---|---|---|
| `Id` | Stable event identifier | Primary key; referenced by saved events |
| `Title` | Event name | Required, non-empty |
| `Category` | Optional event category | Optional; normalized by the event source |
| `StartAtUtc` | Event start instant | Required; persisted consistently as UTC |
| `EndAtUtc` | Event end instant | Optional; if present, must not precede start |
| `TimeZoneId` | Zone used to display the event's local time | Optional only when the source has no zone; sample Cincinnati events use Eastern time |
| `Venue` | Venue or event location | Optional if the source has no location |
| `PriceMin` | Lowest known ticket price | Optional; non-negative when present |
| `PriceMax` | Highest known ticket price | Optional; non-negative and not less than minimum when both are present |
| `TicketUrl` | Optional ticket or source link | Must be a safe absolute HTTP(S) URL when present |
| `SourceName` | Name of the event source | Required for seeded sample records; identifies sample provenance |
| `IsSample` | Indicates illustrative, non-live data | True for development seed events; display an explicit sample-data label |

Relationships: one event may be saved by many users. Saved records reference
the event rather than copying event details.

## SavedEvent

Represents one user's saved relationship to one event.

| Field | Meaning | Rules |
|---|---|---|
| `Id` | Saved relationship identifier | Primary key |
| `UserId` | Owner account identifier | Required foreign key to Identity user; assigned from authenticated principal |
| `EventId` | Saved event identifier | Required foreign key to Event |
| `SavedAtUtc` | Time the user saved the event | Required UTC timestamp |

Relationships: each row belongs to exactly one user and one event. Define
foreign keys to both parent entities, and a unique index/constraint over
`(UserId, EventId)`. Removing a saved row must not delete its event or any other
user's saved row. Deleting a user may cascade to that user's saved relationships.
An event with saved relationships must be retained; remove it from upcoming
listings rather than deleting the referenced record.

## State and validation rules

- A save is allowed only when the event exists and `StartAtUtc` is later than
  the current UTC time at processing.
- An event with a missing or invalid ID cannot create a saved row.
- A repeated save for the same authenticated user/event pair returns the
  duplicate outcome and leaves exactly one row, including when inserts race.
- List and remove queries always include the authenticated `UserId`.
- Removing a missing or foreign user's saved relationship cannot alter any
  other relationship.
- Missing price or venue details do not prevent display of an otherwise valid
  saved event; absent price is rendered explicitly as unavailable.
- Development sample events are deterministic, clearly labeled, and not
  presented as verified live events.

## ERD alignment

The existing ERD already depicts `Users`, `Events`, and `SavedEvents` with
user/event foreign keys and a save timestamp. This model retains that shape,
uses ASP.NET Core Identity as the account source, and adds the unique
user/event-pair constraint required by the specification.
